# Вшивание даты и времени из субтитров

Два режима одного скрипта для Windows 10/11 и Windows Server 2016 с Windows PowerShell 5.1.
Python, установка модулей и права администратора не нужны.

## Зачем выполнять наложение отдельно

Выгрузка из «Линии» с наложением даты и времени на изображение может занимать
много времени. Утилита позволяет вынести наложение и перекодирование
на отдельный мощный компьютер:

1. Быстро выгрузите запись из «Линии» в оригинальном формате с встроенными
   текстовыми субтитрами, без наложения времени на изображение.
2. Перенесите файлы на компьютер для обработки.
3. Запустите `Burn-Timestamp.ps1` напрямую или через CMD-файл CPU/GPU:
   утилита возьмёт дату и время из субтитров, нанесёт их на кадры
   и перекодирует видео в H.264 MP4.

Для этого сценария выгруженный файл должен быть в поддерживаемом контейнере
MP4, MKV, MOV или M4V со встроенной текстовой дорожкой даты и времени.
Так ресурсоёмкая обработка выполняется после выгрузки, с использованием
CPU или NVIDIA GPU выбранного компьютера.

## Запуск двойным щелчком

- **Run-Timestamp-GPU.cmd** — обработка на совместимой видеокарте NVIDIA через NVENC.
- **Run-Timestamp-CPU.cmd** — обработка на CPU, четыре потока по умолчанию.

По умолчанию обрабатываются MP4/MKV/MOV/M4V непосредственно в той же папке,
где находится `Burn-Timestamp.ps1`, независимо от текущей папки консоли.
Вложенные папки не обходятся. Видео должны содержать текстовую дорожку субтитров с датой и временем.
Для переноса готового комплекта на сервер скопируйте его вместе с папкой `bin`
и положите видео рядом со скриптами. После скачивания исходников из Git
сначала добавьте `ffmpeg.exe` и `ffprobe.exe` в `bin`: эта папка исключена из репозитория.

Результаты появляются в подпапке `Timestamp-GPU` или `Timestamp-CPU` рядом с видео.
Имена: `исходное_имя_timestamp_gpu.mp4` / `исходное_имя_timestamp_cpu.mp4`.
Исходники и уже существующие результаты не перезаписываются.
При повторном запуске существующий результат считается ошибкой: задайте другую выходную папку.

## Запуск из PowerShell

В открытой папке комплекта:

Настройки по умолчанию: `-CpuPreset veryfast -Quality 30 -FontName "Microsoft Sans Serif"`.
Качество 30 применяется к обоим режимам: CRF 30 на CPU, CQ 30 на GPU.

```powershell
# Весь каталог: GPU
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Burn-Timestamp.ps1 -Mode GPU -InputPath "D:\Video"

# Весь каталог: CPU, настройки для i5-3450
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Burn-Timestamp.ps1 -Mode CPU -Threads 4 -InputPath "D:\Video"

# Один файл, собственная выходная папка
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Burn-Timestamp.ps1 -Mode GPU -InputPath "D:\Video\camera.mp4" -OutputDirectory "D:\Ready"

# Сначала проверить первые 10 секунд
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Burn-Timestamp.ps1 -Mode CPU -Threads 4 -InputPath "D:\Video\camera.mp4" -PreviewSeconds 10

# На CPU повысить качество по сравнению с настройками по умолчанию
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Burn-Timestamp.ps1 -Mode CPU -Threads 4 -Quality 25 -InputPath "D:\Video"
```

Параметры можно также передавать CMD-файлам, например:
`Run-Timestamp-GPU.cmd -InputPath "D:\Video" -OutputDirectory "D:\Ready"`.

## Изменение размера до 1920×1080

Добавьте `-Resize1080p` к любому режиму:

```powershell
.\Run-Timestamp-GPU.cmd -Resize1080p
.\Run-Timestamp-CPU.cmd -Resize1080p

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Burn-Timestamp.ps1 -Mode GPU -Resize1080p -InputPath "D:\Video"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Burn-Timestamp.ps1 -Mode CPU -Threads 4 -Resize1080p -InputPath "D:\Video"
```

Выходное разрешение — ровно 1920×1080. Пропорции изображения сохраняются;
для видео с другим соотношением сторон добавляются чёрные поля.
Надпись рисуется после изменения размера и автоматически масштабируется под 1080p.
В имени результата появляется `_1080p`, например `camera_timestamp_gpu_1080p.mp4`.
Без этого параметра сохраняется исходное разрешение.

## Стабилизация дрожащего видео

Стабилизация может улучшить восприятие записей с камер, которые раскачиваются
на ветру из-за недостаточно жёсткого крепления: она уменьшает дрожание
изображения и делает просмотр более комфортным.

Добавьте `-Stabilize` к запуску CPU или GPU. По умолчанию стабилизация выключена.

```powershell
.\Run-Timestamp-GPU.cmd -Stabilize
.\Run-Timestamp-CPU.cmd -Stabilize

# Стабилизация вместе с уменьшением до 1080p, проба первых 10 секунд
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Burn-Timestamp.ps1 -Mode GPU -Stabilize -Resize1080p -PreviewSeconds 10 -InputPath "D:\Video\camera.mp4"

# Настройка силы сглаживания и ожидаемой тряски
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Burn-Timestamp.ps1 -Mode CPU -Threads 4 -Stabilize -StabilizationSmoothing 30 -StabilizationShakiness 8 -InputPath "D:\Video"
```

Сначала VidStab анализирует движение исходных кадров (`Analysis`), затем скрипт
стабилизирует изображение, при необходимости меняет размер и наносит дату (`Encoding`).
Надпись рисуется после стабилизации, поэтому не дрожит и не обрезается вместе с кадром.
Промежуточное видео не создаётся: сжатие выполняется один раз, при финальном кодировании.
Анализ добавляет отдельный проход и увеличивает общее время обработки.
В режиме GPU декодирование и финальное кодирование используют NVIDIA,
анализ движения и стабилизация выполняются на CPU. `-SoftwareDecode` также поддерживается.

Параметры действуют только с `-Stabilize`:

- `-StabilizationSmoothing 30` — радиус сглаживания, от 1 до 1000 кадров.
  Большее значение сильнее сглаживает движение, включая намеренные повороты камеры.
- `-StabilizationShakiness 8` — ожидаемая сила тряски, от 1 до 10.
  Большее значение рассчитано на более резкие смещения и может замедлить анализ.

Используется постоянное автоматическое увеличение для компенсации краёв:
часть изображения обрезается, степень обрезки зависит от тряски.
Смазанные при съёмке детали стабилизация не восстанавливает.
С `-PreviewSeconds` анализируется и кодируется только пробный отрывок;
его обрезка может отличаться от обработки полного ролика.

В имени результата появляется `_stabilized`, например
`camera_timestamp_gpu_stabilized_1080p_preview.mp4`.
Исходные временные метки кадров сохраняются; дата берётся из тех же субтитров.
Для функции нужны фильтры `vidstabdetect` и `vidstabtransform` (libvidstab):
включённый в комплект FFmpeg их содержит. При их отсутствии скрипт сообщает ошибку.
Данные анализа удаляются после успеха, при ошибке остаются в папке диагностики.

## Оформление и время

По умолчанию используется чёрный шрифт Microsoft Sans Serif, полужирное начертание,
размер 24 в координатах 2560×1440, нижний правый угол,
без фона, обводки и тени. Размер автоматически масштабируется по высоте видео.

Настройки: `-FontSize 24 -FontName "Microsoft Sans Serif" -MarginRight 0 -MarginBottom 0`.
Отступы задаются в координатах образца 2560×1440 и масштабируются с разрешением.
Потребуется установленный Microsoft Sans Serif или указанный вами шрифт.

Дата и время читаются из первой встроенной текстовой дорожки субтитров.
Для другой дорожки: `-SubtitleStream 1` (нумерация с нуля среди дорожек субтитров).
Ожидаемый текст: `YYYY-MM-DD HH:mm:ss`; HTML-теги шрифта удаляются.
Скрипт не берёт дату из имени файла, системных часов или часового пояса.
Переходы даты, пропуски и скачки времени остаются такими, как в субтитрах.
Внешние SRT и графические субтитры этим скриптом не поддерживаются.

Короткие промежутки до 250 мс между соседними субтитрами закрываются удержанием
предыдущей надписи. В образце есть четыре таких промежутка, самый длинный — 65 мс.
Это предотвращает мигание. `-ExactSubtitleGaps` сохраняет все исходные паузы.
Большие промежутки, начало до первого и конец после последнего субтитра не достраиваются.
ASS хранит время с точностью до 10 мс, поэтому граница смены надписи округляется до этой точности.

## Скорость и размер

GPU: H.265/H.264 декодируется через NVIDIA CUDA, надпись рисуется libass на CPU,
затем видео кодируется в H.264 через NVENC с `p1`, VBR CQ 30, без второго прохода
и lookahead. При проблеме только с аппаратным декодированием добавьте `-SoftwareDecode`:
NVENC при этом остаётся включённым. CUDA-путь рассчитан на 8-битный YUV 4:2:0;
для другого формата используйте `-SoftwareDecode`.

CPU: программное декодирование и H.264 `libx264 -preset veryfast -crf 30`.
Серверный CMD-файл задаёт четыре потока, аппаратное ускорение не используется.
`-CpuPreset superfast` или `ultrafast` увеличивают скорость и обычно размер файла.
Увеличение `-Quality` (например, до 33) уменьшает размер с потерей качества;
уменьшение до 25 повышает качество и обычно размер файла.
Для GPU доступны `-GpuPreset p1` ... `p7`; более высокие пресеты обычно медленнее.
CQ NVENC и CRF x264 имеют разные шкалы восприятия: одинаковое число не гарантирует
одинаковое качество или размер.

Без `-Resize1080p` разрешение сохраняется. Временные метки кадров сохраняются
в обоих случаях; частота принудительно не меняется.
Поворот из метаданных автоматически не применяется: скрипт рассчитан на обычные
неповёрнутые записи камер, как предоставленный образец.
Если есть звук, он перекодируется в AAC 128 кбит/с; дорожка субтитров в результат
не добавляется, дата уже находится в изображении. Выход — MP4 с H.264, faststart.
Вшивание надписи требует перекодирования видео; изображение повторно сжимается.

Размер результата зависит от содержимого и настроек. Переход с H.265 на H.264
может увеличивать файл. Реальная скорость на i5-3450 не измерялась;
проверяйте её пробным запуском на сервере. Производительность ограничивается также
декодированием H.265, фильтром, диском и содержимым записи.

## Переносной FFmpeg и диагностика

В локальном переносном комплекте в `bin` находятся FFmpeg и FFprobe 7.1.1 Essentials
от Gyan.dev с libass, libx264 и NVENC. В Git эта папка не включается.
Для запуска из исходников поместите `ffmpeg.exe` и `ffprobe.exe` в `bin` самостоятельно
или добавьте их в PATH. Для стабилизации сборка также должна содержать libvidstab.
Скрипт предпочитает `bin`, затем EXE рядом со скриптом, затем PATH.
Другую сборку можно указать через `-FFmpegPath` и `-FFprobePath`.

Переносная сборка 7.1.1 проверялась на NVIDIA GeForce RTX 4060 с драйвером 596.49.
Совместимость других сборок и драйверов следует проверять пробным запуском.
Перед каждой GPU-конвертацией выполняется короткая проверка декодера, фильтра
и кодировщика на трёх настоящих кадрах. При отказе нет скрытого переключения на CPU.

Результат публикуется только после успешного завершения FFmpeg и проверки кодека,
разрешения и длительности. Неполный MP4 и промежуточные субтитры при ошибке остаются
в отдельной папке `.timestamp-<идентификатор>` внутри выходной папки; её путь
показывается в консоли. После успеха промежуточная папка удаляется.
Код возврата 0 означает успех, 1 — ошибку хотя бы одного файла.

Во время кодирования отображается процент выполнения текущего видео,
обработанная длительность и скорость, например `Progress: 42% | 8.3/19.7 s | speed 2.5x`.
Показатель обновляется примерно раз в полсекунды и рассчитывается по длительности видео.
С `-PreviewSeconds` процент относится к выбранному отрывку.
До окончания проверки результата показывается не более 99%; 100% появляется
после успешной проверки и сохранения выходного файла. Для каждого видео процент начинается заново.
