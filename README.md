# Инструменты обработки видео для Windows

PowerShell-скрипты для исправления конкретной ошибки MP4, экспортированных из системы видеонаблюдения «Линия», и вшивания даты и времени из встроенных субтитров в изображение. Поддерживаются обработка на CPU или NVIDIA GPU, стабилизация и приведение видео к 1920×1080.

## Зачем нужен проект

### Ошибка при экспорте из «Линии»

По предположению автора проекта, ошибка в экспортированном файле может возникать при кратковременном изменении разрешения записанного видеопотока с камеры. Косвенным признаком является создание нескольких файлов вместо одного при выгрузке выбранного интервала. Связь изменения разрешения с ошибкой пока не подтверждена.

`Repair-LineMp4.ps1` исправляет выявленный в таких MP4 дефект — пустой блок `avcC` — без перекодирования видео, если файл соответствует поддерживаемым условиям.

### Быстрая выгрузка и отдельное наложение времени

Утилита `Burn-Timestamp.ps1` также помогает при долгой выгрузке из «Линии» с наложением даты и времени на изображение. Вместо выполнения всей обработки при экспорте можно:

1. Быстро выгрузить запись из «Линии» в оригинальном формате с встроенными текстовыми субтитрами, без наложения времени на изображение.
2. Перенести выгруженные файлы на мощный компьютер.
3. Наложить дату и время из субтитров и перекодировать видео этой утилитой на CPU или NVIDIA GPU.

Так ресурсоёмкое наложение и перекодирование выполняются отдельно от выгрузки. Для обработки утилитой нужен поддерживаемый контейнер MP4, MKV, MOV или M4V со встроенной текстовой дорожкой даты и времени.

## Возможности

| Инструмент | Назначение | Результат |
| --- | --- | --- |
| `Repair-LineMp4.ps1` | Исправляет пустой блок `avcC` в поддерживаемых MP4 с H.264 после экспорта из «Линии» | Копия `*_repaired.mp4` без перекодирования видеопотока и CSV-отчёт |
| `Burn-Timestamp.ps1` | Наносит дату и время из встроенной текстовой дорожки субтитров | MP4 с H.264 и надписью в кадре; видео перекодируется |

Восстановление MP4 проверяет структуру результата и совпадение SHA-256 медиаданных. По умолчанию исходники сохраняются. Режим `-InPlace` заменяет оригиналы после проверки и не оставляет резервных копий.

При вшивании времени доступны режимы CPU (`libx264`) и GPU (NVIDIA NVENC), пробная обработка через `-PreviewSeconds`, стабилизация `-Stabilize` и разрешение 1080p через `-Resize1080p`. Без изменения размера сохраняется исходное разрешение. Готовые результаты не перезаписываются.

Стабилизация может улучшить восприятие записей с камер, которые раскачиваются на ветру из-за недостаточно жёсткого крепления: она уменьшает дрожание изображения и делает просмотр более комфортным.

## Требования

- Windows с Windows PowerShell 5.1 и .NET Framework. Инструменты рассчитаны на Windows 10/11 и Windows Server 2016; отдельного испытания на Server 2016 не проводилось.
- Для восстановления MP4 дополнительных программ не требуется.
- Для вшивания времени нужны `ffmpeg.exe` и `ffprobe.exe`. Сборка FFmpeg должна поддерживать `libass` и выбранный кодировщик: `libx264` для CPU или `h264_nvenc` для GPU. Для стабилизации нужны фильтры `vidstabdetect` и `vidstabtransform`.
- Режим GPU требует совместимой видеокарты NVIDIA и драйвера. Для CPU видеокарта NVIDIA не нужна.

Python, дополнительные модули PowerShell и права администратора не требуются.

## Подготовка FFmpeg

Папка `bin` исключена из Git. После скачивания исходников поместите `ffmpeg.exe` и `ffprobe.exe` в `bin` рядом со скриптами:

```text
video-tools/
├── bin/
│   ├── ffmpeg.exe
│   └── ffprobe.exe
├── Burn-Timestamp.ps1
├── Repair-LineMp4.ps1
└── Run-*.cmd
```

В локальном переносном комплекте использована сборка FFmpeg 7.1.1 Essentials от Gyan.dev. Ссылки на сборку и её исходники приведены в [подробной инструкции](Timestamp-README.md#переносной-ffmpeg-и-диагностика). При распространении комплекта с FFmpeg приложите его лицензию и сведения о сборке.

Скрипт ищет программы сначала в `bin`, затем рядом с собой, затем в `PATH`. Можно указать пути явно через `-FFmpegPath` и `-FFprobePath`. Для готового ZIP-комплекта с папкой `bin` отдельная подготовка не нужна.

## Быстрый запуск

Запускайте команды из папки со скриптами. Путь `D:\Video` замените на свою папку или файл.

### Восстановление MP4

```powershell
# Проверить файлы без изменений
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Repair-LineMp4.ps1 -Folder "D:\Video" -CheckOnly

# Создать исправленные копии рядом с оригиналами
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Repair-LineMp4.ps1 -Folder "D:\Video"
```

Для запуска двойным щелчком положите `Repair-LineMp4.ps1` и `Run-Repair.cmd` рядом с видео и откройте `Run-Repair.cmd`. Поддерживается перетаскивание папки на этот CMD-файл. `Run-Repair-InPlace.cmd` запускает замену оригиналов без постоянных резервных копий.

### Вшивание даты и времени

```powershell
# CPU: сначала проверить первые 10 секунд одного файла
.\Run-Timestamp-CPU.cmd -InputPath "D:\Video\camera.mp4" -PreviewSeconds 10

# CPU: обработать папку, четыре потока по умолчанию
.\Run-Timestamp-CPU.cmd -InputPath "D:\Video"

# NVIDIA GPU: стабилизация и разрешение 1920×1080
.\Run-Timestamp-GPU.cmd -InputPath "D:\Video" -Stabilize -Resize1080p
```

Без `-InputPath` обрабатываются видео непосредственно в папке скрипта. Результаты сохраняются в `Timestamp-CPU` или `Timestamp-GPU`. Для другой папки результатов используйте `-OutputDirectory`.

## Ограничения

- Восстановление исправляет конкретный дефект контейнера H.264 MP4. Оно не восстанавливает утраченные кадры, артефакты изображения или любые повреждённые видео. H.265 и фрагментированные MP4 этим инструментом не исправляются.
- Вшивание времени требует встроенных текстовых субтитров с датой в формате `YYYY-MM-DD HH:mm:ss`. Время не вычисляется из имени файла или системных часов. Внешние SRT и графические субтитры не поддерживаются.
- Нанесение надписи требует повторного сжатия видео. Стабилизация обрезает часть изображения и не восстанавливает детали, смазанные при съёмке.
