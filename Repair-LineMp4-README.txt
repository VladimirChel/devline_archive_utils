Восстановление MP4 после экспорта из «Линии»
=========================================

Назначение
----------
Исправляет выявленную ошибку экспорта: пустой блок avcC в MP4 с H.264,
где видеопакеты записаны с четырехбайтовыми префиксами длины NAL.
Видеопоток не перекодируется. Дата/время, нанесенные на изображение,
и таблицы временных меток сохраняются.

Работает автономно на Windows Server 2016 с Windows PowerShell 5.1
и штатным .NET Framework. Не нужны Python, FFmpeg, интернет или
дополнительные модули. Права администратора не требуются; необходимы
права чтения исходных файлов и записи в папку для копий/отчета.

Предполагаемая причина ошибки
----------------------------
По предположению автора проекта, ошибка в экспортированном файле может
возникать при кратковременном изменении разрешения записанного потока
с камеры. Косвенный признак — создание нескольких файлов вместо одного
при выгрузке выбранного интервала из «Линии».
Связь изменения разрешения с ошибкой пока не подтверждена.
Утилита исправляет описанный выше дефект avcC в поддерживаемых MP4.

Быстрый запуск
--------------
1. Распакуйте архив. Файлы Repair-LineMp4.ps1 и Run-Repair.cmd должны
   находиться рядом.
2. Скопируйте их в папку с экспортированными MP4.
3. Дважды щелкните Run-Repair.cmd. В конце окно останется открытым.

Проверяется папка, в которой лежит PS1, без вложенных папок.
Результат: имя_исходного_файла_repaired.mp4 рядом с оригиналом.
По умолчанию оригиналы не изменяются. Существующие копии не перезаписываются.
Файлы с именами, оканчивающимися на _repaired.mp4, исключаются из поиска.
Для каждой запускаемой проверки создается новый CSV-отчет в папке поиска.

Можно перетащить нужную папку на Run-Repair.cmd.

Исправление с заменой оригиналов
-------------------------------
Для работы без сохранения отдельных исправленных копий запустите
Run-Repair-InPlace.cmd. Он заменяет проблемные MP4 по прежним именам.
Другой вариант — добавить параметр -InPlace при запуске PowerShell:

powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Tools\Repair-LineMp4.ps1" -Folder "D:\Video" -InPlace

Замена выполняется только после проверки структуры и совпадения SHA-256
медиаданных. Постоянная резервная копия не сохраняется. Ранее созданные
файлы *_repaired.mp4 при этом не удаляются и не используются.
До замены создается временный файл размером примерно с исходный MP4;
соответствующее свободное место все равно необходимо, для одного файла
за раз. После успешной замены временного файла не остается.
Используется штатная операция File.Replace; если файловая система
или права доступа не допускают замену, файл получает статус Error.
Операция удаления оригинала с последующим переименованием не используется.

-InPlace совместим с -Recurse и -CheckOnly, но не с -OutputDirectory.
-CheckOnly -InPlace проверяет возможность замены без изменения MP4.

Запуск из командной строки
------------------------
Примеры, если скрипт находится в C:\Tools:

Исправление MP4 в D:\Video:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Tools\Repair-LineMp4.ps1" -Folder "D:\Video"

Только проверка, без создания исправленных MP4:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Tools\Repair-LineMp4.ps1" -Folder "D:\Video" -CheckOnly

С вложенными папками:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Tools\Repair-LineMp4.ps1" -Folder "D:\Video" -Recurse

Копии в отдельной папке:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Tools\Repair-LineMp4.ps1" -Folder "D:\Video" -OutputDirectory "E:\Fixed"

При -Recurse и -OutputDirectory структура вложенных папок сохраняется.
Папка для копий создается автоматически. Для результата нужно примерно
столько же свободного места, сколько занимают исправляемые файлы.

Свой путь к отчету:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Tools\Repair-LineMp4.ps1" -Folder "D:\Video" -ReportPath "D:\Reports\check.csv"

Папка отчета должна существовать. Существующий отчет не перезаписывается.
Даже в режиме -CheckOnly CSV-отчет записывается.

Для планировщика используйте непосредственно powershell.exe и PS1.
CMD предназначен для ручного запуска и ждет нажатия клавиши в конце.
ExecutionPolicy Bypass действует только в запущенном процессе PowerShell;
скрипт не меняет системные настройки политики выполнения.

Значения Status в отчете
-----------------------
Repaired        — исправленная копия создана; SHA-256 видеоданных совпадает.
RepairedInPlace — оригинал заменен после проверки; резервной копии нет.
WouldRepair     — проверка пройдена, файл можно исправить; включен -CheckOnly.
AnnexBUnchanged — пустой avcC, но поток в Annex B; эта ошибка открытия к нему
                  не относится. Файл не изменяется.
NoTargetDefect  — поддерживаемая ошибка пустого avcC не найдена.
                  Это не означает проверку воспроизведения всего видео.
OutputExists   — копия уже существует; она не изменялась и не проверялась.
Unsupported    — случай не поддерживается или неоднозначен; причина в Message.
Error          — ошибка структуры, доступа, записи или контрольной проверки.

SamplesChecked/VideoBytesChecked относятся к видеопотокам, пригодным для
данного исправления. Для NoTargetDefect/AnnexBUnchanged они могут быть нулевыми.
MediaSha256 — SHA-256 объединенного содержимого всех mdat в порядке их записи;
включает все медиаданные, в том числе звук, если он есть. Это не хеш всего MP4.

Коды завершения
---------------
0 — обработка завершена; ошибок и неоднозначных пропусков нет.
    В -CheckOnly файлы со статусом WouldRepair также дают код 0.
1 — хотя бы один Error либо ошибка запуска/создания отчета.
2 — ошибок Error нет, но есть Unsupported или OutputExists: проверьте отчет.

Что именно проверяется
----------------------
Для целевого потока проверяются все видеопакеты: соответствие таблицам MP4,
расположение внутри mdat, четырехбайтовые длины NAL, заголовки NAL, наличие
SPS/PPS в первом пакете и их неизменность по всей части. Из SPS/PPS строится
конфигурация avcC. При смене параметров внутри файла исправление не выполняется.

Сначала создается временный файл *.partial. Затем проверяется структура
результата и SHA-256 всех медиаданных. Только после совпадения хешей файл
получает окончательное имя *_repaired.mp4 либо заменяет оригинал в режиме
-InPlace. Обычные ошибки до замены удаляют временный файл, сохраняя оригинал.
После принудительного завершения процесса/отключения питания может
остаться .partial. Partial-файлы не
участвуют в поиске MP4 и никогда не считаются готовыми копиями.

Поддерживаются обычные MP4 с moov в конце или начале/середине файла,
таблицами stco/co64 и stsz. Если moov расположен не в конце, прежний moov
помечается как свободное место, а исправленный добавляется в конец;
смещения медиаданных при этом сохраняются.

Ограничения
-----------
Это исправление конкретного дефекта контейнера, а не универсальное
восстановление поврежденных видео. Скрипт не декодирует изображение
и не восстанавливает полосы/артефакты, уже присутствующие в видеоданных.
Не выполняется конвертация H.265 или работа с зашифрованными потоками.
Фрагментированные MP4 и файлы с sidx/mfra пропускаются. Поддерживается одна
запись avc1 в таблице описаний каждого исправляемого видеопотока и локальная
ссылка data_reference_index=1. Поддерживаются H.264 профилей 66, 77, 88,
100, 110, 122, 144. SPS/PPS должны присутствовать в первом видеопакете.
Защитные пределы: moov до 256 МиБ, видеопакет до 64 МиБ, до 10 млн сэмплов
на исправляемый видеопоток. Размер всего MP4 не ограничен 4 ГБ.

Исходный файл открывается без разрешения параллельной записи. В режиме
-InPlace разрешена операция замены/переименования, чтобы заменить файл
с открытым дескриптором чтения, сохраняя запрет записи в исходные данные.
Если экспорт еще работает с этим файлом, будет ошибка доступа; запустите
обработку после завершения экспорта.

Проверка реализации
-------------------
Скрипт запущен в Windows PowerShell 5.1.26100 на двух проблемных файлах
пользователя. Исправленные копии целиком совпали по SHA-256 с ранее
восстановленными и проверенными декодированием файлами. Рабочий Annex B
файл оставлен без изменений. Дополнительно проверены тесты moov в начале,
нулевого размера последнего mdat, co64, расширенного заголовка moov,
поврежденных смещений, обрезанного файла, смены SPS и уже исправленного MP4.
Проверен ручной запуск CMD с именем файла на кириллице, пробелами и #,
а также код завершения 2 и сохранение готовых копий при повторном запуске.
Режим -InPlace проверен на тех же девяти тестовых случаях: результаты
совпадают с обычными копиями, файлы сохраняют прежние имена, временные
файлы убираются. Проверено сохранение оригинала при ошибке замены
из-за блокировки, отсутствие изменений с -CheckOnly и отказ сочетания
-InPlace с -OutputDirectory.
Проверка выполнялась на доступной Windows с PowerShell 5.1; отдельного
стенда Windows Server 2016 в этой среде не было.
